Create the account from either side, a recovery key for backups, and reaching your server on Android 17.

- Fixed: on Android 17, Connect to server said "The server can't be reached" for a server on the phone's own Wi-Fi network, even when the phone's browser reached it. Android 17 blocks an app from the local network unless it has the local network permission (Nearby devices), and the app didn't ask for it. Connect and QR pairing now ask for it, once.
- A failed connect now says what failed: plain HTTP refused, the local network permission off, the server's name not found, the connection refused, no answer in time, no route to the address, an https:// failure, or something answering that isn't a Dead Drop server. The address can be typed as host:port, http://host:port or https://host:port. Plain http:// goes only to a home network, tailnet or loopback address; https:// goes anywhere.
- Backups now use a recovery key instead of a password: 256 random bits, made on your first backup (or when the server account is created) and shown once, in 14 groups of 4, with Copy and I saved it. It is never shown again. Lose it and the backups made with it are gone. Backups made before 1.6.0 still restore with their password.
- With a server account, the account has one recovery key and your devices pass it to each other through your server, sealed so the server can't read it. A backup made on one device opens on any of them.
- The desktop program can create the server's account too. Log in has Stay logged in, on by default; unticked, closing the app logs this phone out and the next open asks for the login again.
- More > Server > Password: a logged-in phone can set a new account password, typed twice, without the old one. Your other devices stay logged in. There is no password reset on the server, so keep the password safe.
- Requires Android 13 or newer.
